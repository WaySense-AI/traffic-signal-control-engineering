# 第 17 章 MaxBand 双向绿波

早高峰的三路口干线被调成了一条明显的正向绿波：西向东的车队一路遇绿，反向车辆却几乎在每个路口都吃红灯。工程师把这种结果称为“正向优先”。方案交付时，反向的抱怨最先到——只为单个方向调出来的偏移，代价由没进模型的方向分摊。

第 16 章的表 16-3 把问题摆上了桌面：偏移取 0、10、20、80 秒，正反带宽沿四组数字此消彼长。那张表给出了结果，却给不出选择偏移的依据。选择这个偏移的依据是什么？它是否明确记录了速度范围、双向需求和交叉方向牺牲，还是只来自一次人工试验？

MaxBand 把这类决策放进约束优化：在周期、路段速度、绿灯窗口、左转相序和带宽权重条件下，同时选择相位差并最大化正反方向带宽。这就是路线图里说的“第 17 章把偏移扩展成 MaxBand 优化”。

MAXBAND 的原始模型和程序目标可参考 [6]。本章的变量说明以 WaySense 当前实现和教学简化为主，不把某一份实现当作原始论文的完整复刻。

## 17.1 带宽到底表示什么

在时空图上，车辆轨迹是时间—距离平面中的斜线。斜率由速度决定。

```text
time ->
distance
  |
```

若一条轨迹在通过每个协调路口时都位于绿灯内，它属于绿波带。带宽是带宽内的出发时刻形成一个连续时间窗口，不是各路口绿灯时长的总和。

例如两个路口各有 40 秒绿灯，车辆行程时间为 10 秒。如果下游绿窗没有按行程时间平移，最大公共出发窗口只有 30 秒。两个绿窗相同不代表带宽等于 40 秒。

## 17.2 单向偏移是 MaxBand 的退化情况

先忽略双向和速度变化。相邻路口使用同一周期 `C`。如果上游协调绿灯开始于 `o_i`，车辆到下游需要 `t_i`，理想下游绿灯开始为：

```text
o_{i+1} = (o_i + t_i) mod C
```

理论行程时间：

```text
t_i = d_i / v
```

`d_i` 是路段长度，`v` 是设计和实际车队的代表速度。

SignalLab：

```python
segment = CorridorSegment("S1", "S2", 240, 36)
segment.travel_time_s  # 24s
downstream_offset_s(0, segment, 150)  # 24s
```

这个结果只说明几何偏移。完整方案还要确认绿窗、相位位置、排队清空和协调阶段。

## 17.3 双向冲突从哪里产生

正向偏移优化后，车辆从上游到下游在 `t_forward` 后到达。反向车辆从下游返回上游，需要 `t_reverse`。

当道路和周期固定时，两个方向的绿窗通常不能同时达到最大。最简单的两路口例子：

```text
cycle = 100s
two-way travel time = 20s
green duration = 40s
```

改变下游偏移：

具体见表 17-1。
表 17-1 双向冲突从哪里产生
| 下游偏移/s | 正向带宽/s | 反向带宽/s | 说明 |
|---:|---:|---:|---|
| 0 | 20 | 20 | 双向折中 |
| 10 | 30 | 10 | 正向优先 |
| 20 | 40 | 0 | 完全正向 |
| 80 | 0 | 40 | 完全反向 |

这张表不是“哪个偏移更正确”的答案，而是说明运营者必须选择方向权重。

WaySense 的方向权重设置：

```text
双向均衡 -> 1
正向优先 -> 0.1
反向优先 -> 10
```

这些系数进入目标函数，而不是直接决定带宽秒数。

## 17.4 从绿窗到约束

MaxBand 通常在周期比例空间计算：

- `b`：正向带宽占周期比例
- `b_bar`：反向带宽占周期比例
- `w_i`：路口 `i` 正向绿窗位置
- `w_bar_i`：反向绿窗位置
- `r_i`、`r_bar_i`：绿窗外不可用于协调带的红窗比例
- `t_i`、`t_bar_i`：正反方向行程时间比例

核心窗口约束可以概括为：

```text
w_i + b <= 1 - r_i
w_bar_i + b_bar <= 1 - r_bar_i
```

这表示带宽必须落在可用绿窗内。某路口红灯比例增加，会压缩可用的 `w`。

相邻路口还需要周期平衡和行程时间关系。源码中的完整方程还包含：

- 左转保护相序变量 `delta`
- 路段排队清空时间 `tau`
- 周期环绕辅助变量 `m`
- 正反方向行程时间边界

这些项共同保证相位差、速度和绿窗在同一个周期基准上闭合。

### 17.4.1 一个可复算的固定周期模型

为了避免把生产模型简化为几条口号，可以写出一个不含左转保护和清空修正的两路口连续时间模型。所有时间除以公共周期 \(C\)，因此带宽、行程时间和窗口位置都位于 \([0,1)\)。

变量为：

- \(b\)：正向带宽比例；
- \(\bar b\)：反向带宽比例；
- \(w_1,w_2\)：正向上游、下游绿窗位置；
- \(\bar w_1,\bar w_2\)：反向上游、下游绿窗位置；
- \(m_f,m_r\)：周期环绕的整数变量。

固定周期、固定速度时，模型可以写成：

\[
\begin{aligned}
\max\;&b+k\bar b\\
\text{s.t.}\;&0\le w_i\le 1-r_i-b\\
&0\le \bar w_i\le 1-\bar r_i-\bar b\\
&w_2=w_1+t_f-m_f\\
&\bar w_1=\bar w_2+t_r-m_r\\
&m_f,m_r\in\mathbb{Z}\\
&b,\bar b\ge0
\end{aligned}
\]

目标中的 \(k\) 是反向带宽相对权重。\(r_i\) 表示绿窗外不可用于协调带的比例，\(t_f,t_r\) 是正反向标准化行程时间。若周期为 100 秒、行程 20 秒、绿窗 40 秒，则 \(t=0.2\)、\(r=0.6\)。把 \(w_1=0\)、\(m_f=0\) 代入，得到 \(w_2=0.2\)，即下游绿窗在 20 秒处开始。此时 \(w_2+b\le0.4\) 允许 \(b\le0.2\)，正向带宽最多 20 秒。

这个模型只解释最核心的窗口和行程时间关系。生产实现还会加入：

- 周期上下界；
- 速度上下界；
- 绿灯起点和终点的不同协调定义；
- 左转保护相序变量；
- 排队清空比例；
- 路段方向权重和非协调阶段约束。

把它误解为“完整 MAXBAND 就只有这几个方程”，会把模型结果与工程事实混在一起。

### 17.4.2 为什么需要整数环绕变量

若去掉 \(m_f\)，约束 \(w_2=w_1+t_f\) 只能表示一个周期内的前进相位，无法表达车辆在下一周期到达同一绿窗。\(m_f\) 记录“跨过了几个完整周期”。它的值必须为整数；允许小数会把周期相位变成连续平移，产生实际上不存在的非周期对齐。

整数变量也解释了求解难度。固定周期和速度时，变量维数不大，可以用线性规划或混合整数规划求解；加入多路口、周期选择、速度和左转相序后，模型规模和组合关系增加。实际算法会在可接受时限内寻找可行或接近最优解，并返回求解状态。用户界面不能只展示带宽，还要展示是否证明最优、是否超时以及哪些约束限制了解。

数值实现还必须处理浮点容差。若某条约束的理论边界是 \(b=0.2\)，求解器返回 0.2000000001，验收器不能因为微小误差拒绝或接受整个方案。应先把比例转换为设备秒数，再用整数扫描复核；边界容差和取整方向都应写入配置。

### 17.4.3 不可行诊断应定位到约束

“带宽为零”至少有三种可能：

1. 模型确实可行，但任何偏移都无法形成连续带；
2. 模型不可行，求解器没有返回解；
3. 模型返回解，但取整或设备字段转换后不可执行。

只有第一种可以重新设计偏移；第二种要放宽周期、速度、绿窗或最小带宽；第三种要修复转换层或增加取整安全余量。系统应返回无解约束、求解器状态和目标值，不能把三种情况都折叠为“绿波计算失败”。

### 17.4.4 生产模型里周期是变量：z = 1/C

17.4.1 的模型把周期固定为 C，这是为了手算。生产实现不是这样：周期在模型里是决策变量，而且以倒数形式出现。

为什么要取倒数。模型里的绿窗位置、行程时间和带宽都是“占周期的比例”，真实秒数等于比例乘周期。若周期是变量，约束里会出现“比例 × C”的双线性项；令 `z = 1/C`，把时间变量都定义成比例，约束就重新变成线性的。

代码在 `maxband.py`：

```python
cycle = round(1 / z)
if any(dc) and cycle % 2 != 0:
    cycle += 1
```

双周期场景强制偶数周期，因为半周期关系要求 `C/2` 仍是整数。

这段代码也解释了结果形态，但不能推出“周期必然贴顶”。目标 `max b + k·b_bar` 里的 `b`、`b_bar` 都是周期比例，周期只通过 `z` 和速度约束改变可行域；目标本身没有“秒数越大越好”的项。周期取上限是求解结果中常见的边界现象，不是目标函数的单调性结论。

要判断某次结果是否真的贴顶，应检查求解器返回的 `z` 是否等于 `1/C_max`、对应约束是否 active，并用改变 `C_max` 的对照实验验证；不能只看一眼输出周期就宣布“算法偏好长周期”。

所以“带宽最大化”和“周期最小化”是对立的。如果运营目标是“在可接受带宽下尽量短周期”，就不能直接最大化带宽，而要加周期惩罚或约束，再比较 Pareto 前沿。书里给的固定周期算例只回答“这个周期下带宽是多少”，不回答“该选哪个周期”。

## 17.5 周期与速度是变量

如果只固定周期和速度做相位差，问题会简单很多，但允许速度在合理范围内变化、周期在设备范围内选择，找到的带宽通常更大。

生产实现允许：

```text
C_min <= C <= C_max
d_i / speed_max <= t_i <= d_i / speed_min
```

其中 `d_i / speed_max` 是速度较快时的最短行程时间，`d_i / speed_min` 是速度较慢时的最长行程时间。

这也解释了为什么输出可以同时包含“周期、偏移和协调速度”。速度不是固定为 40 km/h，而是在设计容差内成为协调变量。

## 17.6 目标函数

最简目标为：

```text
maximize b + k * b_bar
```

其中 \(k\) 反映反向带宽相对正向的权重。

也有人使用加权 `b + k*b_bar`，并结合：

- 最小带宽约束
- 双向带宽比例
- 交通需求权重
- 周期和速度惩罚

目标函数只能决定“什么算更好”。安全与结构约束必须独立存在。

### 17.6.1 带宽权重是方向之间的交换比率

权重的作用方向要按目标函数读：目标为 \(b+k\bar b\)，\(k=0.1\) 是**正向优先**，模型愿意用最多 10 秒反向带宽换 1 秒正向带宽；\(k=10\) 是**反向优先**，愿意用最多 10 秒正向带宽换 1 秒反向带宽；\(k=1\) 才是双向同权。它描述的是优化偏好，不是 10 倍的交通收益。真正的方向需求、排队、下游溢出和支路牺牲仍要通过约束与独立评价检查。

还要注意 \(k=10\) 在双周期模型里被复用为控制分支标志（27.3），那里的 10 不表示“反向权重 10 倍”。同一个数字在两处承担不同语义，方案报告必须写明它属于哪一层。

一组方案可以形成 Pareto 前沿：在不降低另一方向带宽的情况下无法继续提高某一方向。运营人员需要看到前沿上的几个点，而不是只看到某个权重下的一条记录。若权重变化没有改变方案集合，说明进入目标的变量被固定，或者求解器没有真正读取配置。

## 17.7 一个完整的双向算例

两个路口，周期 100 秒，两个方向绿窗各 40 秒，正反方向行程均为 20 秒。

### 均衡优先

选择下游偏移 0 秒。正反带宽都约为 20 秒。两个方向对速度和出发波动的容忍度较低，但没有方向被完全牺牲。

### 正向优先

选择偏移 20 秒。正向可得到约 40 秒连续带宽，反向带宽接近 0。车辆仍然可以在反向方向通行，但无法形成连续绿波。

因此，输出“正向带宽 40 秒”并不意味着干线总体上优于均衡方案。必须同时报告反向结果。

## 17.8 时空图复核

优化器得到方案后，应把结果重新放回时空图：

```text
for each offset candidate:
    map each intersection green interval onto common cycle
    apply travel time by direction
    measure continuous passing interval
```

SignalLab：

```python
green_band_width_s(

```

反向扫描不应简单复用正向结果，除非速度、拓扑和时间基准都对称。

## 17.9 代码走读

WaySense 的 `maxband.py` 包含多个模型版本：

- `MaxbandLP1`
- `MaxbandLP2`
- `MaxbandBLP`
- `MaxbandBLPDC`

公共步骤包括：

1. `prepare_maxband_input_table_static` 建立路段顺序、距离和速度范围。
2. `prepare_maxband_input_table_dynamic` 把各路口方案转换为红窗、绿窗和左转比例。
3. `prepare_maxband_input_table_tau` 准备排队清空比例。
4. `optimization` 建立周期、带宽、窗口、行程时间和相序变量。
5. 求解器最大化双向带宽。
6. 结果转换为周期、偏移和阶段方案。

实现同时使用 CVXPY 和 Python-MIP 风格模型。它们不是在重复同一算法，而是针对线性、混合整数和双周期等不同形式。

## 17.10 清空时间：公式里有，实现里是 0

MaxBand 的约束和相位差公式里都有排队清空时间 `tau`。但在当前实现里，它恒为 0。

`lightflow/settings.py`：

```python
TAU_DEFAULT = 0.0
```

`maxband.py`：

```python
@staticmethod
def prepare_maxband_input_table_tau():
    '''
    # TODO: 增加排队清空时间计算逻辑（支路转入车辆预排队长度计算）
    路口清空时长tau的计算逻辑并没有完成, 后续需要补充完善。目前是直接用TAU_DEFAULT个周期代替。
    路口清空时长tau理论上很重要, 对相位差的影响很大。
    '''
    return TAU_DEFAULT, TAU_DEFAULT
```

调用点 `maxband.py` 把这一对默认值批量赋给所有路口：

```python
maxband_input_table['tau'], maxband_input_table['tau_bar'] = \
    cls.prepare_maxband_input_table_tau()
```

因此：

- 约束里的 `tau` 项退化为 0；
- 相位差公式里的 `- tau[i+1]` 退化为 0；
- 等价于假设排队在绿窗开始时瞬时消散。

WaySense 实现注释里写明“对相位差的影响很大”。对饱和度高、转弯排队长的路口，忽略清空会让偏移偏乐观：模型认为车辆能连续通过，现场却要等前一个周期的排队先走完。

工程上必须区分两件事：

1. 模型是否有 `tau` 这一项；
2. 这一项是否被真实标定。

只有第一条成立时，不能宣称协调方案考虑了排队清空。若系统只能取 0，方案报告里应显式标注“未计排队清空”，并把该路口列为需要现场复核的对象。

## 17.11 数值尺度

MaxBand 常在周期比例空间求解，最后再乘周期转换为秒：

```text
offset_seconds = offset_fraction * cycle
band_seconds = band_fraction * cycle
```

因此模型中的 `b=0.2` 在 100 秒周期下是 20 秒，在 150 秒周期下是 30 秒。比较模型输出时必须同时看周期。

整数秒转换后还要验证：

```text
offset in [0, cycle - 1]
green windows remain valid
band recomputation is consistent
```

一个具体换算例子：模型给出正向带宽比例 \(b=0.2\)、反向带宽比例 \(\bar b=0.1\)，周期从 100 秒改为 92 秒。带宽分别从 20 秒、10 秒变为 18.4 秒、9.2 秒。设备若以整数秒执行，正向带宽向下变为 18 秒，不能把模型值四舍五入成 18 秒后仍假设反向也有完整 9 秒。

比例空间的约束也可能在取整后恰好落空。例如绿窗和带宽边界刚好相等，浮点求解器返回可行，整数偏移后可能越界 1 秒。转换层必须把偏移和带宽重新放回扫描器，检查每个路口的绿窗覆盖。模型可行、取整方案不可行是正常的数值边界，不应被 UI 隐藏。

验收记录还应保留求解器状态、目标值、变量边界和不可行约束名。只有一份偏移表，无法区分“没有更好解”和“求解器在时限内停止但尚未证明最优”。

## 17.12 求解失败

不可行的常见原因：

- 周期上下限不包括共同周期
- 速度范围过窄
- 绿窗无法容纳最小带宽
- 左转相序与方案冲突
- 清空时间比例异常
- 路口顺序或方向错误

求解失败时，系统应返回约束诊断，而不是给出全零带宽或静默沿用旧方案。

求解失败还有一个更隐蔽的出口。`post_opt_process` 在 `status != optimal` 时不会抛错，而是把周期加 20 秒并沿用原相位差（`maxband.py` 的 `post_opt_process`）：

```python
seg_maxband_output_table['StagePlan'] = seg_maxband_output_table['StagePlan'].apply(
    lambda x: setattr(x, 'cycle', cycle + 20) or x)
```

调用方拿到的是一份“新方案”，看不到失败。验收时必须读 `status` 字段，并检查“输出周期是否恰好等于输入周期加 20”这一特征；否则会把一次失败当成一次优化。

## 17.13 本章实验

运行：

```bash
cd signal-lab
python3 -m examples.experiment_coordination
```

实验要求：

1. 固定速度和绿窗，比较多个偏移。
2. 缩放绿窗，观察带宽上界。
3. 改变周期，理解比例和秒数差异。
4. 设计一个正向权重 10 的方案，并记录反向损失。
5. 加入不可行约束，验证错误返回。

实验还要求记录：

```text
solver_status
objective_value
cycle_fraction_or_seconds
base_offsets
forward_band_fraction
reverse_band_fraction
integer_rounding_delta
recomputed_band_seconds
infeasible_constraint
```

若优化器给出的 18.4 秒带宽在整数设备偏移上重新扫描只有 17 秒，应报告取整损失，而不是继续使用模型值作为验收结果。

带宽是优化目标，不是安全证书。关键证据缺失时，结果只能作为候选方案。

## 17.15 小结

第 16 章把偏移逐段算到了走廊上，本章把偏移连同周期、速度一起交给约束优化：权重是方向之间的交换比率，清空时间在实现里还是 0，求解失败会伪装成周期加 20 的“新方案”。理解该算法需要区分三类对象：

```text
交通绿窗：哪些车辆可以通行
模型变量：带宽、窗口、速度、偏移和相序
工程方案：设备可以执行的周期和阶段
```

三者之间必须经过转换和校验。优化成功只证明模型找到解，真实路口是否安全有效，要靠转换后的扫描和现场复核来回答。模型给出的偏移和带宽终究是比例空间里的数字，方案要回到可观察的时间—空间关系上检验——第 18 章把时空图从示意图变成验收工具，本章 17.8 那次复核就是它的雏形。

**生产映射（第 27 章 生产区域协调与 MaxBand 源码）**

- 27.2 的 `prepare_maxband_input_table_dynamic` 把单点方案转成占比空间的 `maxband_input_table`。
- 27.3 的 `MaxbandBLPDC` 中 `k=10` 复用为控制分支标志，周期强制取偶。
- 契约约定 `maxband_output_table` 输出 `Cycle`、`offset_abs`、`b`、`b_bar`、`sol_v`、`sol_v_bar`。
- 教学层返回带宽比例和求解状态；生产层 `status != optimal` 时周期加 20 静默沿用（17.12）。
